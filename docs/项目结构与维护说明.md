## 0. 一句话概览

一个极简的 Android 临时邮箱客户端：单 Activity + 单文件 Compose 架构，通过 PearAPI 生成一次性邮箱、拉取邮件，支持 WebView 渲染邮件正文、验证码一键复制、历史邮箱复用、15 种语言与深色模式，并内置基于 GitHub Releases 的自更新（含 SHA-256 校验）。

| 项 | 实际值 | 来源 |
|---|---|---|
| 包名 / applicationId | `com.tempmail.app` | `app/build.gradle.kts` |
| versionCode | `9` | 同上 |
| versionName | `1.9` | 同上（`BuildConfig.VERSION_NAME`） |
| minSdk / targetSdk / compileSdk | 24 / 34 / 34 | 同上 |
| JVM target | 17（`sourceCompatibility`/`jvmTarget`） | 同上 |
| 主源码规模 | `MainActivity.kt` **1896 行** + 主题 3 文件共 54 行 | `wc -l` 实测 |
| release APK | `app/build/outputs/apk/release/app-release.apk`（约 1.3 MB） | 构建产物 |

> ⚠️ **README 与代码已出现漂移**，维护时以代码为准：

## 3. 架构与状态模型

### 3.1 整体结构

```
MainActivity : ComponentActivity
└── onCreate → enableEdgeToEdge() → setContent
    └── TempMailTheme(darkTheme = state.isDarkMode)      ← 不读系统深色设置
        └── Scaffold (snackbarHost + bottomBar = NavigationBar 三 Tab)
            ├── showDisclaimer == true  → 免责声明 + "性别选择" 拦截页
            └── showDisclaimer == false → AnimatedContent(targetState = state.currentTab)
                ├── Tab.Inbox    → InboxTab(...)
                ├── Tab.History  → HistoryTab(...)
                └── Tab.Settings → SettingsTab(...)   ← 内部再套 SettingsPage 二级导航
        + 全局 showUpdateDialog / showDownloadProgress 两个 AlertDialog
```

### 3.2 单一状态源 `AppState`

```kotlin
data class AppState(
    val email: String = "",            // 当前生效邮箱
    val count: Int = 0,                // 服务端返回的 count 字段
    val rawMessages: List<String> = emptyList(),  // 解析失败时的原始 receivedata
    val items: List<EmailItem> = emptyList(),     // 已解析并去重合并的邮件
    val isLoading: Boolean = false,
    val history: List<HistoryEmail> = emptyList(),// 过期邮箱（内存态）
    val currentTab: Tab = Tab.Inbox,
    val isDarkMode: Boolean = false,
    val language: String = "zh",
    val autoCheckUpdate: Boolean = true
)
```

- 唯一持有者：`MainActivity.onCreate` 内的 `var state by rememberSaveable(stateSaver = AppStateSaver)`。
- 所有子 Composable 通过 `onState: (AppState) -> Unit` 回写整份 state（**不可变整体替换**，非字段级更新）。
- 子页面为 `@Composable private fun` 顶层函数（非成员），状态靠参数透传 —— 无 ViewModel、无 CompositionLocal 业务状态。

### 3.3 其他数据模型

| 类型 | 定义位置 | 字段 |
|---|---|---|
| `EmailItem` | L465 | `from, subject, time, body, htmlBody, timestamp: Long` |
| `HistoryEmail` | L474 | `email, isActive` |
| `Language` | L71 | `code, label` |
| `Strings` | L91 | 约 48 个 UI 文案字段（含 `gender*`、`close`、`copyCode`、`networkError` 等） |
| `PoemLine` | L1685 | `line, title, author` |
| `enum Tab` | L459 | `Inbox, History, Settings`（携带 `ImageVector`） |
| `enum SettingsPage` | L1269 | `Main, Language, DarkMode, About, Author` |

### 3.4 状态持久化（两条独立通道）

1. **SharedPreferences**（`getSharedPreferences("app", MODE_PRIVATE)`）
   - `language` / `isDarkMode` / `autoCheckUpdate` / `disclaimer_accepted`
   - 启动时读取初始化 `AppState`；设置页改动时写回（`MainActivity` 的 `SettingsTab` 回调内比对后存入）。
2. **`rememberSaveable` + `AppStateSaver`**（`Saver<AppState, String>`）
   - `appStateToJson`(L1812) / `appStateFromJson`(L1846) 把整份 state 序列化成 JSON 字符串，用于**配置变更 / 进程重建**恢复。
   - 细节：`isLoading` 不持久化；`rawMessages` 只保留最近 **5** 条以控制 Bundle 体积；`Tab` 以 `ordinal` 存储。

## 4. 核心功能与数据流

### 4.1 邮箱生成
```
点击"生成新邮箱" (InboxTab, L941)
  → onState(state.copy(isLoading=true))
  → scope.launch(Dispatchers.IO) → GET https://api.pearapi.ai/api/email/?type=get
  → JSONObject(code=="200") → email
  → 若旧 email 非空：history + HistoryEmail(旧邮箱, isActive=false)
  → onState(email=新邮箱, count=0, items=[], rawMessages=[], history=新, isLoading=false)
```
⚠️ 邮箱生成**不写 SharedPreferences**，仅依赖 `AppStateSaver` 跨配置变更存活。

### 4.2 刷新收件
```
点击"刷新" (L1000)
  → 记录 emailAtRefresh = state.email
  → doRefresh(email) (L673)：GET .../api/email/?type=receive&email=<HttpUrl 参数编码>
  → code=="200" → 回传 (count, receivedata 原文)
  → 回调内先做竞态守卫：state.email != emailAtRefresh 则丢弃结果
  → parseEmails(raw, s.unknownSender) → List<EmailItem>
  → mergeEmailItems(state.items, newItems)   // 按 from|subject|time 去重，只增不减
  → rawMessages = rawMessages + listOf(raw)  // 追加，内存持续增长
  → snackbar：raw 为空 → "暂无新邮件"；merged 为空 → "解析异常"
```
- 排序在渲染层：`compareByDescending { timestamp }.thenByDescending { time }`（`remember(state.items)` 缓存）。
- `count` 直接取服务端字段展示，与 `items.size` **不一致是正常的**。
- 调试日志标签：`MAIL_DEBUG`、`MAIL_LINK`、`POEM_DEBUG`（release 由 ProGuard 抹除）。

### 4.3 邮件详情与链接跳转
- 点击列表项 → 计算 `dialogBody`（`body` → 无则 `stripHtml(htmlBody)`）与 `dialogHtml`，弹 AlertDialog。
- 正文用 `AndroidView { WebView }` 渲染：`javaScriptEnabled=true`、`domStorageEnabled=true`、`allowFileAccess=false`、背景透明。
- 载入策略：有 `htmlBody` → `loadDataWithBaseURL("https://example.com", …, "text/html")`；否则按 `looksLikeHtml()` 判定 html 或 plain。
- **三重链接拦截**（保证验证邮件按钮可点）：
  1. `WebViewClient.shouldOverrideUrlLoading` 新旧两版重载 → `openMailLink`
  2. `WebChromeClient.onCreateWindow` 处理 `target="_blank"` → 新建临时 WebView 同样接 `openMailLink`
  3. `onPageFinished` 注入 `mailLinkJs`（捕获阶段拦截 `a[href]` 并 `window.location.href`）
- `openMailLink`(L1672) 只放行 `http/https/mailto/tel`，一律 `Intent.ACTION_VIEW` 交系统浏览器/拨号，WebView 不留驻。

### 4.4 验证码识别与复制
- `extractVerificationCode`(L1762) 依序匹配 4 条正则：中文提示词（验证码/校验码/激活码/确认码/动态码）、英文 `code is/:`、`code below/above/here`、最后兜底独立 4–8 位数字（用负向先行断言排除年份 `20xx`）。
- 命中则在 AlertDialog 的 `dismissButton` 位置显示"复制验证码"，写入剪贴板并 toast。

### 4.5 历史记录
- 列表 = `[当前邮箱(isActive=true)] + history.reversed()`。
- 点击"已过期"条目 → 当前邮箱先入 history，再从 history 中移除目标，切换为当前邮箱并清空邮件列表。
- **内存态**：不写盘，杀进程即失；仅靠 `AppStateSaver` 在配置变更/进程重建时保留。

### 4.6 设置
| 项 | 行为 |
|---|---|
| 语言 | `allLanguages` 15 项；改动写 SharedPreferences，并即时重算 `strings(lang)` |
| 深色模式 | 开关写 SharedPreferences，直接驱动 `TempMailTheme(darkTheme=…)` |
| 检查更新 | `onCheckUpdate(true)` → `checkUpdate(isManual=true)` |
| 自动检查更新 | 开关写 SharedPreferences；`LaunchedEffect(Unit)` 启动时若开启则 `checkUpdate()` |
| 关于 | 展示 `aboutDesc` |
| 作者信息 | 硬编码链接：GitHub 主页 / 项目仓库 / Blog；Email 与微信号为纯文本（不可点） |
| 版本号 | 底部显示 `BuildConfig.VERSION_NAME`（仅 Main 页） |

### 4.7 自更新链路
```
checkUpdate(isManual) (L630)
  → GET https://api.github.com/repos/wzhdgithub/tempmail/releases/latest
    (header: Accept: application/vnd.github.v3+json)
  → tag_name 去 "v" 前缀，versionCompare(tag, BuildConfig.VERSION_NAME)   // L1725 逐段数字比较
  → <=0 → 手动则提示"已是最新版本"
  → assets[0].browser_download_url
  → SHA-256 取值优先级：asset.digest 去 "sha256:" 前缀 → 发版说明中匹配 64 位十六进制
  → 弹 AlertDialog（标题含版本、正文为 release body）

点击"在线更新" → downloadInstall(url, sha) (L561)
  → sha 为空则直接拒绝（防篡改）
  → Android 8+ 先检查 canRequestPackageInstalls()，否则跳 ACTION_MANAGE_UNKNOWN_APP_SOURCES
  → Dispatchers.IO 流式下载到 getExternalFilesDir(null)/updates/app-release.apk
    （边下边 MessageDigest 累积，8KB buffer，按 contentLength 算进度回调主线程）
  → 摘要不符 → 删除文件 + 提示失败
  → 相符 → FileProvider("${packageName}.fileprovider") + ACTION_VIEW + FLAG_GRANT_READ_URI_PERMISSION 拉起安装
```
注意：只取 `assets[0]`，不按文件名/ABI 匹配。

### 4.8 免责声明拦截页（非文档化功能）
- 首次启动 `disclaimer_accepted == false` → 全屏展示 `disclaimerText`（硬编码中文，8 条条款）+ 一个"性别选择"单选。
- 只有选择 **"其他 / other"** 才能通过；选 male/female 会提示"该性别已被占用"并阻塞。
- 通过后写 `disclaimer_accepted=true`，`showDisclaimer` 用普通 `remember`，故拦截页本身不参与状态恢复。

### 4.9 随机诗句 banner（非文档化功能）
- `LaunchedEffect(Unit)` → `withContext(Dispatchers.IO) { fetchRandomPoemLine(client) }`，仅执行一次。
- 依次尝试 `https://poetry.palemoky.com/api/v1/poems/random` → `/api/poems/random`；解析 `data.title / data.author.name / data.content`，随机取一行。
- 成功则 `AnimatedVisibility(fadeIn + slideInVertically)` 淡入展示，带书名号与作者。

## 6. 外部服务、权限与资源

### 6.1 网络端点（全部 HTTPS）
| 用途 | 端点 |
|---|---|
| 生成邮箱 | `GET https://api.pearapi.ai/api/email/?type=get` |
| 收件查询 | `GET https://api.pearapi.ai/api/email/?type=receive&email={email}` |
| 版本检查 | `GET https://api.github.com/repos/wzhdgithub/tempmail/releases/latest` |
| 诗句 | `GET https://poetry.palemoky.com/api/v1/poems/random`（及 `/api/poems/random` 备用） |

- 响应约定：`code == "200"` 视为成功；`receivedata` 是 **字符串形式的 JSON**，需二次解析。
- `network_security_config.xml` 仅显式声明 `api.pearapi.ai`（`cleartextTrafficPermitted="false"`）；因 targetSdk 34，其余域名默认同样禁明文。
- `OkHttpClient` 单例（`remember` 创建）：connect/read timeout 各 15s，无拦截器、无缓存。

### 6.2 权限与组件（`AndroidManifest.xml`）
- 权限：`INTERNET`、`REQUEST_INSTALL_PACKAGES`
- `android:allowBackup="false"`、`tools:ignore="TestOnly"`
- 唯一 Activity：`.MainActivity`（LAUNCHER）
- `FileProvider`：authority `${applicationId}.fileprovider`，路径配置指向 `external-files-path updates/`
- 非数据库应用：**无 Room/SQLite/网络缓存**，唯一磁盘写入是更新 APK

### 6.3 资源文件
- `drawable/`：`ic_launcher.xml`（纯 Vector，`#1976D2` 信封图案），无 mipmap、无 adaptive icon。
- `values/strings.xml`：仅 `app_name = 临时邮箱`。
- `values/themes.xml`：`Theme.TempMailApp` 父主题为 `android:Theme.Material.Light.NoActionBar`（始终亮色，与 App 内深色开关无关）。
- **无 `values-xx/` 多语言资源** —— 15 种语言全部在 `MainActivity.kt` 内以 `Strings` 数据类实现。

## 7. 构建、签名与发布

```powershell
# 需先设置 JAVA_HOME（README 建议 JDK 24）
$env:JAVA_HOME = "C:\Program Files\Java\jdk-24"
./gradlew :app:assembleDebug
./gradlew :app:assembleRelease   # 输出 app/build/outputs/apk/release/app-release.apk
```

**签名逻辑**（`app/build.gradle.kts` 顶部）：
1. 读根目录 `keystore.properties`（`storeFile` / `storePassword` / `keyAlias` / `keyPassword`）；
2. 缺失则回退环境变量 `KEYSTORE_PASSWORD` / `KEY_PASSWORD`；
3. `hasReleaseKeystore` 为 false 时 **完全不创建 signingConfig** → debug 用默认调试签名、release 不签名。

**ProGuard**：
- `isMinifyEnabled = true` + `isShrinkResources = true`
- `-assumenosideeffects class android.util.Log { … }` 抹除全部日志（防止邮箱/验证码进 logcat）
- `-dontwarn okhttp3.**` / `-dontwarn okio.**`
- `-keepclassmembers class com.tempmail.app.network.** { *; }` —— **该包在当前源码中不存在，属历史残留死规则**。

**其他构建要点**：
- Gradle wrapper 走腾讯云镜像（`mirrors.cloud.tencent.com`），离线/内网构建友好。
- `gradle.properties` 中 `android.injected.testOnly=false`，配合 `adbOptions { installOptions("-t") }` 适配部分国产 ROM 对 testOnly 包的拦截。
- 仓库根目录**只有 `gradlew.bat`，没有 `gradlew` shell 脚本**（Linux/macOS CI 需另行补 `chmod +x gradlew` 或重新 `gradle wrapper`）。

> 🔐 **安全提示**：`keystore.properties` 虽已 gitignore，但当前磁盘上存有**明文 store/key 密码**，与 `app/keystore.jks` 同处工作区；分享工程目录、打包 zip、或误删 `.gitignore` 都会泄露签名凭据。建议改为环境变量注入或使用加密凭据管理。

| 1 | **`Strings` 是 data class，含约 48 个字段且无默认值** | 新增任何文案字段，必须同步补齐 `strings()` 内 **全部 15 个语言分支 + else 分支**，否则编译失败。v1.8→1.9 就因新增 `close/copyCode/codeCopied/networkError/queryFailed/fetchFailed/unknownSender` 而全量改动。 |
| 2 | **新增语言需改两处** | `allLanguages` 列表 + `strings()` 的 `when` 分支，漏一处则语言可选中但文案回落中文。 |
| 3 | **`AppState` 加字段必须同步改序列化** | 漏改 `appStateToJson`/`appStateFromJson` → 配置变更后该字段静默丢失。 |
| 4 | **`Tab` 以 `ordinal` 持久化** | 调整 `Tab` 枚举顺序会让恢复后的 tab 错位（老存档 JSON 的 `tab` 数字含义改变）。 |
| 5 | **`rawMessages` 只增不减** | 每次刷新都追加原文；仅持久化时截断为 5 条 → 长会话内存单调增长。 |
| 6 | **`mergeEmailItems` 只增不减** | 去重键为 `from|subject|time`；同键不同内容的新邮件会被丢弃，且删除/过期邮件无法从列表移除。 |
| 7 | **`count` 与列表长度不等** | 展示用服务端 `count`，列表是可累积去重结果，用户可能看到"3 封"但列表 10 条。 |
| 8 | **深色模式双轨** | `themes.xml` 固定亮色，Compose 侧由 `state.isDarkMode` 控制且默认与系统无关 → 系统深色下首次启动/闪屏为亮色。 |
| 9 | **硬编码中文未本地化** | 免责声明全文、`"你真的选对了吗?"`、`"同意并进入"`、`"原始数据:"`、作者页 `"作者主页"/"项目仓库"/"微信"`、Email 与微信号等，切换语言不变。 |
| 10 | **免责声明"性别门槛"是拦截逻辑** | 该页非纯展示，改动其条件会影响**所有新用户的进入路径**（且 `disclaimer_accepted` 一旦写入无法在 App 内重置，只能清数据）。 |
| 11 | **`_keepclassmembers com.tempmail.app.network.**` 失效** | 指向不存在的包；若未来真引入 R8 相关反射类，别误以为已有保护。 |
| 12 | **更新链路只信任 `assets[0]` 与哈希存在性** | 无签名/包名校验；`sha` 非法时拒绝下载是当前唯一防线，改动时请勿放宽。 |
| 13 | **`FileProvider` 路径已收窄为 `updates/`** | 更新包存放位置若调整，须同步改 `file_paths.xml`（历史版本曾用 `path="."`）。 |
| 14 | **WebView 开启 JS 且高权限渲染邮件** | 已做 `allowFileAccess=false` + scheme 白名单 + 外跳浏览器；任何"为兼容性放开 file:// 或 addJavascriptInterface"的改动都会引入严重安全面。 |
| 15 | **单文件架构** | 1896 行同文件、3 个 Composable 顶层函数、状态经参数透传；任何跨功能改动都可能波及 UI 与状态两条链路，建议先跑 `assembleDebug` 验证。 |
| 16 | **工作区有未提交改动** | 当前 `.gitignore / README / app/build.gradle.kts / proguard-rules.pro / MainActivity.kt / file_paths.xml` 均相对 HEAD 有修改（v1.9 内容），建议修改前先提交或建分支，避免与后续改动混淆。 |

## 9. 快速自检清单（改动后）

1. `./gradlew :app:assembleDebug` 通过（尤其动了 `Strings`/`AppState` 后）。
2. 生成邮箱 → 复制 → 刷新 → 列表中点击邮件 → 正文链接可跳转浏览器。
3. 含验证码的邮件 → 弹窗出现"复制验证码"。
4. 切换语言（至少中文/英文/阿语 RTL）与深色模式，确认无残留未本地化文案。
5. 旋转屏幕/后台被杀后返回 → 邮箱、邮件列表、历史、当前 Tab 均恢复。
6. 历史页点击过期邮箱"使用" → 正确切换且列表清空。
7. release 构建后用 `logcat` 确认 `MAIL_DEBUG` 等日志已被移除；验证 APK 哈希校验路径（可临时改错哈希看是否拒绝安装）。
